# 8. Cross-cutting Concepts

Cross-cutting concepts apply uniformly across all components. They are not owned
by a single building block; instead each adapter or domain component implements
them according to the rules defined here.

## 8.1 Input Validation

**Where:** `Validator` component (domain core); enforced before any simulation runs.

**Rules (FR-7):**

| Check | Condition that triggers rejection |
|-------|----------------------------------|
| Empty grid | `width < 1` or `height < 1` |
| Start position outside grid | `x < 0`, `x >= width`, `y < 0`, or `y >= height` |
| Start position on obstacle | `(x, y)` is in `grid.obstacles` |
| Unknown command character | Any character in the command string other than `F`, `L`, `R` |

**Contract:** `Validator.validate(request: SimulationRequest) -> None`. Raises
`ValidationError(message: str)` on the first failing check. Does not raise on an
empty command list (zero commands is valid; the rover stays at the start position).

**HTTP mapping:** the FastAPI Route Adapter catches `ValidationError` and returns HTTP 400
`{"error": "<message>"}`. All other unhandled exceptions propagate as HTTP 500
`{"error": "internal error"}` (see §8.2).

## 8.2 Error Handling

**Principle:** errors are classified at the boundary and never leak internal detail
to the caller.

| Error class | Origin | HTTP status | Response body | Logged? |
|-------------|--------|-------------|---------------|---------|
| `ValidationError` | `Validator` | 400 | `{"error": "<validation message>"}` | Yes (`WARNING`) |
| Unhandled exception | Any component | 500 | `{"error": "internal error"}` | Yes (`ERROR` with traceback) |

**FastAPI Route Adapter error-handling pattern:**

```python
try:
    request = deserialise(request_body)
    validator.validate(request)
    result = executor.execute(request)
    return http_200(result)
except ValidationError as exc:
    logger.warning("validation_error", error=str(exc))
    return http_400(str(exc))
except Exception:
    logger.exception("unhandled_error")
    return http_500("internal error")
```

The domain core (`Validator`, `CommandExecutor`, `Navigator`) never catches
exceptions; it raises them. Only the FastAPI Route Adapter contains try/except blocks.

## 8.3 Logging

**Where:** `Logger Adapter` (`rover/adapters/logger.py`), called by the FastAPI
Route Adapter after every request (success, validation error, and unhandled error).

**Format:** every log entry is a single-line JSON object written to stdout. Docker
captures stdout and `docker logs` reads it; no log shipper or cloud service is used.

**Mandatory fields in every log entry:**

| Field | Type | Example |
|-------|------|---------|
| `level` | string | `"INFO"` |
| `event` | string | `"simulation_complete"` |
| `request_id` | string | Per-request identifier generated by the FastAPI Route Adapter (UUID4) and passed to the Logger Adapter |
| `grid` | `{width, height, obstacle_count}` | `{"width":10,"height":10,"obstacle_count":2}` |
| `start` | `{x, y, heading}` | `{"x":0,"y":0,"heading":"N"}` |
| `command_count` | int | `5` |
| `result` | object or null | `{"x":0,"y":2,"heading":"N","blocked_count":1}` |
| `error` | string or null | `null` |
| `duration_ms` | float | `3.7` |

**Log levels:**

| Situation | Level |
|-----------|-------|
| Successful simulation | `INFO` |
| Blocked command(s) in an otherwise valid simulation | `INFO` |
| Validation error | `WARNING` |
| Unhandled exception | `ERROR` (with `exc_info=True`) |

**No PII or secrets** are written to logs. The grid content (obstacle coordinates)
is summarised as a count; individual obstacle positions are not logged.

## 8.4 Security

**Input trust boundary:** the HTTP endpoint is unauthenticated in the MVP (noted as
a risk in Chapter 11). All input is treated as untrusted; the `Validator` runs before
any simulation logic.

**Secrets:** there are no secrets in the MVP. `LOG_LEVEL` is the only environment
variable; it carries no sensitive data. If a future integration requires a secret,
it must be injected via environment variables (e.g. a local `.env` file excluded
from version control) — never hard-coded or logged (TC-8).

**Least privilege:** there is no cloud IAM role. GitHub Actions pushes images with
the automatic `GITHUB_TOKEN` scoped to `packages: write` (Chapter 7.4); the container
needs no elevated privileges or mounted Docker socket.

**Dependency scanning:** `bandit` (static analysis) and `detect-secrets` (credential
scanning) run in the pre-commit hook and in CI on every push (CV-1).

## 8.5 Testability

**Principle:** every component is testable in isolation without Docker or a network
(TC-7, quality goal 2).

| Component | Test type | How isolated |
|-----------|-----------|-------------|
| `Validator` | pytest unit | Instantiated directly; no mocks needed |
| `Navigator` | pytest unit | Instantiated directly; no mocks needed |
| `CommandExecutor` | pytest unit | Instantiated with a real `Navigator`; no mocks needed |
| Domain core end-to-end | pytest-bdd | `Validator` + `CommandExecutor` + `Navigator` called directly from step definitions |
| `FastAPI Route Adapter` | pytest unit | Exercised via FastAPI's `TestClient` with a synthetic JSON request; no network or container is needed |

BDD feature files in `tests/bdd/features/simulate.feature` are the primary
specification for FR-4 through FR-7 and serve as the acceptance criteria reviewed
by the course instructor.
